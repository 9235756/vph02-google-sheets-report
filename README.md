# Генератор отчётов в Google Sheets

Домашнее задание к уроку **VPh02. Кейс 1. Автоматический отчёт в Google Sheets**.

В проекте две части:

1. `google_sheets.py` — переиспользуемый модуль. Класс `GoogleSheets` умеет читать и записывать Google Таблицу через Google Sheets API v4 и оформлять её. Авторизация идёт через сервисный аккаунт по JSON-ключу.
2. `report_generator.py` — десктоп-приложение «Генератор отчётов» на tkinter. Оно генерирует случайные отчётные данные и записывает их в таблицу отдельным оформленным листом.

Все данные вымышленные: имена менеджеров и названия компаний придуманы, реальных персональных данных в проекте нет.

## Структура

```

```

## Что умеет `google_sheets.py`

| Группа | Методы |
|---|---|
| Листы | `get_sheet_names()`, `get_sheet_id(title)`, `add_sheet(title)`, `delete_sheet(title)` |
| Чтение | `read_all_cells(sheet)`, `read_range(range)` |
| Запись текста (RAW) | `write_range(range, values)`, `write_ranges(data)`, `append_rows(sheet, rows)`, `update_cell(cell, value)` |
| Запись формул (USER_ENTERED) | `write_formula(cell, formula)`, `write_formulas(range, values)`, `write_formula_ranges(data)` |
| Очистка | `clear_range(range)` |
| Оформление (batchUpdate) | `format_range`, `merge_cells`, `set_borders`, `set_column_width`, `set_row_height`, `freeze_rows`, `auto_resize_columns`, `add_banding` |

`format_range` задаёт цвет фона, цвет и размер шрифта, жирность, выравнивание, перенос и числовой формат: `number`, `decimal`, `currency`, `percent`, `date` или свой шаблон.

Как модуль обходит две проблемы из урока:

- **`\xa0` при чтении.** В денежном формате Google Sheets разделяет разряды неразрывным пробелом. `read_range` и `read_all_cells` заменяют его обычным пробелом, схлопывают повторяющиеся пробелы и обрезают края. Чтобы превратить строку вида «12 345,00 ₽» в число, есть функция `parse_number`.
- **Строки, начинающиеся с `+`, `=` или `-`.** Текст записывается с `valueInputOption="RAW"`, поэтому «+7 999…» остаётся строкой, а не превращается в формулу с ERROR. Формулы пишутся отдельными методами в режиме `USER_ENTERED`. Если передать им обычный текст, они откажутся его записывать.

Ошибки модуль переводит в понятные исключения:

| Исключение | Когда |
|---|---|
| `CredentialsFileNotFoundError` | нет файла JSON-ключа |
| `InvalidCredentialsError` | файл ключа повреждён, пустой или ключ отозван |
| `PermissionDeniedError` | сервисный аккаунт не добавлен редактором таблицы или Google Sheets API не включён |
| `SpreadsheetNotFoundError` | неверный `SPREADSHEET_ID` |
| `SheetNotFoundError` | нет такого листа или диапазона |

Все они наследуются от `GoogleSheetsError`. Если не хватает переменных в `.env.local`, поднимается `ConfigError` из `config.py` со списком того, чего не хватает.

## Как выглядит лист отчёта

Новый лист называется «Отчёт ДД.ММ.ГГГГ–ДД.ММ.ГГГГ ЧЧ-ММ». Если за ту же минуту уже создан отчёт, к имени добавляется « (2)». Колонки A–G:

| Строки | Содержимое |
|---|---|
| 1 | Объединённая шапка: компания и тип отчёта, белый текст на тёмно-синем |
| 2 | Период, менеджер или отдел, время формирования |
| 5–6 | Итоги: выручка по оплаченным сделкам, количество сделок, средний чек, конверсия в оплату. Значения считаются формулами по таблице |
| 8 | Шапка таблицы: цветная, закреплена при прокрутке |
| 9… | Детализация: №, дата, клиент, менеджер, сделка, сумма (денежный формат), статус (цвет по значению). Строки чередуются по цвету, ячейки в рамках |
| после таблицы | «Итого» `=SUM(...)` и «Среднее по сделке» `=AVERAGE(...)` |

Сетка листа скрыта, ширина колонок рассчитывается по самому длинному значению. Всё оформление отправляется одним запросом `batchUpdate`. Если запрос упал на середине, недоделанный лист удаляется.

## Установка и настройка

### 1. Проект в Google Cloud

Откройте [Google Cloud Console](https://console.cloud.google.com/), нажмите **New Project** и назовите проект «Excel Factory».

### 2. Включить Google Sheets API

**APIs & Services → Library** → найдите «Google Sheets API» → **Enable**.

### 3. Сервисный аккаунт

**APIs & Services → Credentials → Create credentials**. Выберите **Application data**, затем **Service account**, имя — «backend», роль — **Editor** или **Owner**.

### 4. JSON-ключ

Откройте созданный сервисный аккаунт → вкладка **Keys → Add key → Create new key → JSON**. Скачанный файл положите в корень проекта, например под именем `service_account.json`.

> Файл ключа никогда не должен попасть в репозиторий. `.gitignore` уже исключает все `*.json`, кроме `*.example.json`. Если ключ всё же утёк на GitHub, Google его автоматически заблокирует: удалите ключ в Cloud Console и создайте новый.

### 5. Таблица и доступ

Создайте Google Таблицу «Отчёт». Нажмите **Настройки доступа** и добавьте email сервисного аккаунта с правами **Редактор**. Email указан в поле `client_email` JSON-ключа и выглядит как `backend@<project-id>.iam.gserviceaccount.com`.

### 6. ID таблицы

ID — это часть URL между `/d/` и `/edit`:

```
https://docs.google.com/spreadsheets/d/<ВОТ_ЭТО_ID>/edit#gid=0
```

Скопируйте `.env.local.example` в `.env.local` и заполните:

```
GOOGLE_CREDENTIALS_PATH=service_account.json
SPREADSHEET_ID=<ID таблицы>
REPORT_COMPANY_NAME=ООО «Пример»
```

Если вставить в `SPREADSHEET_ID` весь URL, программа сама извлечёт из него ID.

### 7. Окружение и запуск

```bash
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt

python google_sheets.py            # проверка доступа: листы и ячейки первого листа
python report_generator.py         # окно «Генератор отчётов»
```

tkinter входит в стандартную библиотеку Python. Если на macOS с Python из Homebrew появляется `No module named '_tkinter'`, установите `brew install python-tk`.

## Ожидаемое поведение

Ниже описано, как программа должна работать по замыслу кода. Это не записанный результат запуска: при разработке приложение не запускалось и к Google API не обращалось. Проверьте всё сами по сценарию ниже.

- `python google_sheets.py` выводит пронумерованный список листов, затем строки первого листа через ` | `. При ошибке настройки печатает одну понятную строку о том, чего не хватает, и завершается с кодом 1.
- `python report_generator.py` открывает окно с полями «Дата с», «Дата по», «Тип отчёта», «Менеджер или отдел», «Количество строк» и «Название компании». По умолчанию период — с первого числа текущего месяца по сегодня.
- При неверной дате, периоде «с» позже «по» или числе строк вне диапазона 1–1000 появляется окно с ошибкой, и генерация не начинается.
- После нажатия «Сгенерировать отчёт» кнопка блокируется, прогресс-бар и строка статуса показывают этапы работы, окно при этом остаётся отзывчивым. В конце появляются ссылка «Открыть отчёт в Google Таблице» и кнопка «Скопировать ссылку».
- Если `.env.local` не заполнен, при старте показывается предупреждение со списком недостающих настроек.

## Тесты

Тесты не требуют сети и ключей: Google API заменён на `MagicMock`, а сборка отчёта проверяется на фейковом клиенте.

```bash
pip install -r requirements-dev.txt
pytest -q
```

Что проверяется:

- очистка `\xa0` и лишних пробелов, разбор денежных строк;
- строки с `+`, `-`, `=` пишутся в режиме RAW, формулы — в USER_ENTERED;
- 403 и 404 превращаются в `PermissionDeniedError` и `SpreadsheetNotFoundError`, отсутствие файла ключа — в `CredentialsFileNotFoundError`;
- валидация дат (формат, несуществующая дата, «с» ≤ «по») и количества строк;
- генерация данных: границы периода, фильтр по отделу, воспроизводимость с seed;
- построение запросов `batchUpdate`: A1 → GridRange, поля `repeatCell`, рамки, ширина колонок, закрепление строк;
- раскладка отчёта: формулы ссылаются на нужный диапазон, недоделанный лист удаляется при сбое;
- проверка `.env.local`.
